# Bongo Planet — local output protocol version1

The browser connects to `ws://127.0.0.1:5418`; the bridge binds loopback and accepts Origin `http://127.0.0.1:5417`. The inspectable HTTP receiver is `http://127.0.0.1:5418/receiver`. Actual UDP ADM-OSC is sent only to the configured loopback test receiver5419. This build does not connect to a venue or qualify spatial synthesis.

Every WebSocket JSON message carries `version:1` and a strict discriminated `type`. Unknown fields, unsupported versions, nonfinite values and invalid sound parameters are rejected. The maximum message size is128KiB. `sync` exchanges browser monotonic `t0` and server monotonic seconds; midpoint conversion records round-trip uncertainty. A reconnect clears its previous conversion until the new handshake completes.

`start` names a unique transport session, resetting independent control/position sequence streams. `heartbeat` keeps that session alive. `position` carries stable nodeId, positive integer objectId, normalized composition XYZ, monotonic sent time and its position sequence. `trigger` carries control sequence, immutable triggerSequence, trigger ID ending in that sequence, generatorId, nodeId/objectId, converted onset seconds and committed sound. `cancel` lists exact trigger IDs and/or node IDs; it cancels pending work and releases corresponding active test voices. `stop` invalidates the session and releases all work. Retired sessions and nonincreasing/replayed sequences are rejected. Positions must precede their triggers.

The browser's sound-node-to-integer mapping starts with FNV-1a of the stable stringID, modulo2,147,483,646 plus1. New node names are sorted, then collisions resolve by linear probing; existing active mappings remain unchanged. Scene replacement resets the mapping; ordinary movement preserves it. The receiver rejects an integer reassigned to another active name. Generators have no sound-object mapping.

Each position produces actual OSC address `/adm/obj/{objectId}/xyz`, type tag `,fff`, and three big-endian float32 values. Both string fields are NUL-terminated/padded to multiples of four bytes. Coordinates remain x=right, y=forward, z=up; camera rotation never transforms them. Raw hex and decoded UDP receipts are retained in receiver evidence. Six exact cardinal vectors independently test the transport; F07 uses actual nearest mesh vertices, recorded separately.

The receiver limits active objects to92, pending events plus unresolved cancellation receipts to5376 and test voices to64. Its oldest-insertion voice policy is a control demonstration. Events received more than20ms late or more than12s ahead are rejected. An active node cannot change its integer object ID until node cancellation removes that binding.

The CLI bridge starts a private Node worker whose native monotonic clock owns the ordered control queue, positions, numerical voices and actual deadline execution. Node validates producer traffic and forwards it immediately. Both threads read process hrtime; a fixed startup conversion maps Node performance seconds into that shared native domain. Every actual control mutation retains independent before/after hrtime readings, its intended native deadline, execution-time XYZ, clock incarnation, fixed conversion, held-out bracket and separate report arrival. No audio frame, sample offset or device presentation is inferred from a native receipt.

Before starting one producer session, the adapter takes eight sequential independent clock exchanges. It retains the tightest valid half-round-trip interval and its corresponding offset, adding a conservative1ms timestamp allowance. It exposes all eight observed tuples in diagnostics, rejects malformed replies, times out an unanswered probe after2s, and ignores unsolicited sync messages after calibration. A tiny measured round trip does not imply unlimited timer precision: Chromium's [time-clamping source](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/timing/time_clamper.h) defines a100µs coarse resolution. Complete Safari timing qualification remains open.

The performance-to-Node synchronization bound does not independently qualify the audio-to-performance conversion. The audio processor can correct repeated worklet clocks by advancing its render cursor within a20ms limit, while external trigger conversion still reads the main AudioContext clock. The relationship between those clocks during correction needs live correlation evidence; the correction's isolated PCM regression cannot establish remote timing for a sustained frozen-clock case. That boundary remains open.

Native startup brackets hrtime around performance.now() 32 times and fixes the narrowest valid origin interval. Additional startup and periodic one-second windows retain all 32 held-out brackets. The lifetime uncertainty covers the farthest bracket endpoint around that unchanged conversion; incompatible origin intervals or a bound above10ms fail closed. Eight actual cross-thread probes independently verify parent-send ≤ worker-observation ≤ parent-receipt. Neither callback errors nor product onsets fit the clock conversion.

Ordinary worker timers execute due controls. The worker reads the native clock at the actual numerical voice mutation, checks ±20ms lateness before and after insertion, and restores any evicted voice if a late write must be rolled back. A blocked parent cannot move the worker's observed timestamp to its deadline. Parent report delay remains separate. Each due row rechecks shared poison, the500ms producer lease and the1500ms calibration-budget expiry; a buffered heartbeat cannot revive an expired epoch. Cancel/stop receipts and applied-command acknowledgements remain ordered, so an already executed onset reported after cancellation is retained without reviving a voice.

The worker bounds pending controls at5376, numerical voices at64, objects at92, outstanding command bytes at262144 and receipts at8192 rows /2MiB. Batches are capped at64 rows /61440 bytes and require ordered acknowledgements within500ms. A private196608-byte IPC envelope accommodates the external128KiB packet plus internal clock metadata; it does not increase the external protocol limit. Capacity, clock, incarnation, sequence, witness or worker failures visibly release the session. Invalid execution evidence synchronously poisons the worker, latches bridge readiness false and prevents a reconnect from admitting a new epoch. Shutdown retains errors and closes network resources even when worker cleanup fails. There is no automatic timer fallback or implicit restart.

The two-argument createBridge API retains the original Node timer mode for diagnostic/unit comparisons. CLI launch selects native-monotonic; --render-clock explicitly selects the retained private AudioWorklet diagnostic. The earlier timer receiver failed F01 at178/180 despite early queueing. The later render diagnostic passed F01 at180/180, but interrupted F04 after19.718seconds above its10ms combined uncertainty gate, then failed its independent mapping guard. Those immutable failures remain in [attempt02](../evidence/step-09/render-clock-qualification/attempt-02/live-report.json). The [independently reviewed native hypothesis](../evidence/step-09/receiver-worker-probe/Independent-Review.md) executed6048 sustained controls exactly once and remained active during100/250ms parent stalls. Production native integration and sustained fixture qualification are recorded separately; the hypothesis does not grant venue acceptance. state.clock exposes native readiness, held-out brackets and worker state; state.timing retains parent scheduling diagnostics.

A50Hz position service operates independently of rendering. Movement interpolation lasts120ms; unsent positions coalesce per object. Native WebSocket buffer above64KiB prevents further positions; prolonged500ms congestion disconnects. Reliable controls are never coalesced; control-buffer failure disconnects immediately. Heartbeats are100ms; after500ms without one the receiver invalidates the session and closes the producer socket. Reconnect sends current positions and starts a new session, without replaying missed triggers.

Schema source is `src/output/protocol.ts`; browser adapter is `src/output/OutputAdapter.ts`; actual receiver is `src/output/bridge.ts`. The artifact reports distinguish source-adapter stress tests, real receiver receipt traces, and the outstanding physical venue path. Version1 has no public/LAN authentication model; those routes require a separate configured and qualified venue design.
