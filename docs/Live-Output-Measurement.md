# Bongo Planet — live output measurement

## Acceptance boundary

Offline WAVs, event timestamps, and an AudioWorklet simulation do not establish actual browser-output timing. The live gate in Rules.md requires at least 120 actual output onsets spanning F02/F03, F06, and maximum-supported F08; compensated median error ≤5 ms, p95 ≤10 ms, maximum ≤20 ms; and 100/250 ms main-thread stalls without missing/duplicate ordinary events. Fixed latency must be estimated from isolated probes before evaluating the remaining observations. Only that measured constant may be removed. Safari, listening, and audiovisual timing remain separate checks.

Two completed captures establish the named virtual route and measure the actual product adapter. The analytic run renders the original MonoSynth inside a live AudioWorklet. The product run plays the immutable application bundle through its actual AudioAdapter, Engine, and synthesis processor. Both send audio to a named Core Audio virtual output and record the matching named virtual input. The full live gate remains open because F03 and dense timing observations use documented variants, individual original dense-mixture onsets remain unidentified, and Safari is untested.

## Existing devices and explicit selection

`system_profiler SPAudioDataType` identifies Orbisonic Aux Cable (64 input/output channels), SPAT 8ch loopback (9 input/output channels), and other virtual devices. The observed system default is MacBook Pro Speakers at 48 kHz; its default input is the physical microphone. The test never requests the default input.

Chrome exposes the labels with a `(Virtual)` suffix. The harness grants enumeration permission in a disposable Playwright profile, enumerates devices, selects the exact named virtual input/output pair, then requires `deviceId: { exact: selectedVirtualInputId }`. It checks the returned track identity before capture. A missing ID or mismatched track stops the run. No `getUserMedia({audio:true})` call occurs. No ambient microphone is opened, no driver is installed, and no system default route is changed.

The earlier dense soak used Orbisonic Aux Cable as its per-context output. The final candidate’s continuously recorded soak uses the explicitly selected SPAT 8ch loopback input/output pair; its own report is authoritative. The analytic probe uses SPAT 8ch loopback to avoid mixing with that soak's output. If another application feeds the chosen device, the baseline capture must expose that contamination and the timing result must remain unqualified.

Chrome supports per-context output routing through `AudioContext.setSinkId`; device enumeration can expose non-default devices when microphone permission is granted. [Chrome implementation guidance](https://developer.chrome.com/blog/audiocontext-setsinkid) The mandatory `exact` device-ID constraint prevents a unavailable preferred input from falling back to another device. [Media capture constraints](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

## Harness and retained evidence

Run `npx tsx scripts/live-output-probe.ts` for the analytic probe, or `BONGO_PROBE_MODE=product npx tsx scripts/live-output-probe.ts` for actual product playback. Both require the immutable evidence-only snapshot server on port 5420, supplied by the running soak. The analytic mode additionally imports the original synth source module from the permanent development server on port 5417; the product mode imports no mutable source. The harness uses the installed `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, headless, with test-profile permission and background-throttling options recorded in the report. Fake permission UI is allowed for the explicitly selected virtual device; fake input audio is not used.

Artifacts are written under `evidence/step-05/live-output/`:

- `probe-report.json`: selected device identities, browser, actual input track settings, actual output sink, sample rate, capture status, baseline peak, calibration latency, individual expected/measured errors, stalls, missing/duplicate counts, and limitations.
- `named-virtual-capture.f32`, when capture completes: actual device-input samples, mono little-endian Float32 at the report's sample rate. This is a recording of the virtual input, not an offline render.
- `named-virtual-capture.wav`: the same actual samples in Float32 WAV, with no normalization or resynthesis. `jitter.csv` contains individual measured errors.
- `product/`: actual adapter report, raw recording, WAV, jitter CSV, independent reference fixtures/vertices, chunk metadata, and retained first-play observer failure.
- `probe-report-enumeration-label-mismatch.json`: preserved initial attempt. It stopped before opening any input because the first exact label comparison did not include Chrome's suffix.

The first 12 isolated live onsets estimate fixed latency; the next 120 independently scheduled 30°/60°/90° analytic cases measure compensated jitter. At 120 BPM, period 4, travel fraction 0.75, the expected travel delays are 250/500/750 ms. Captured onset sample times come from the capture worklet's audio clock; MessagePort delivery times are not used as audio onset times. Main-thread stalls are scheduled and their actual durations retained. Every capture track and context is stopped/closed after the attempt.

## Status and remaining full-gate work

Playwright adds `--mute-audio` by default in headless launches. An early headless attempt retained allzero input and cannot establish a driver failure: its browser output was muted. Both scripts now explicitly remove that default and record `Browser.getBrowserCommandLine`, refusing a run if the actual argument vector still contains mute.

The initial label-mismatch attempt is a recorded failure of enumeration selection, with no recording opened. A later headed attempt was interrupted by page navigation; its report is retained as `probe-report-navigation-interruption.json` without a timing claim. A further completed capture attempt reached analysis but failed on a tsx-generated browser helper; its failure is retained as `probe-report-analysis-helper-failure.json`. The corrected harness now retains chunks incrementally as `named-virtual-capture-partial.f32` with `capture-chunks.jsonl`, even if later analysis fails. The corrected attempt's measured status is in the actual report; do not infer success from this document or from a running process.

Full product timing still needs identified actual onsets from the original F03/F06/F08 compositions on the recorded reference route and required browsers. Expected times must be calculated independently from composition geometry, emission rules, tempo, and deterministic voice ownership. Dense mono mixtures need a validated onset-identification method that accounts for the declared voice-steal policy; simply counting engine events does not count audible onsets. Retain individual measured errors, raw capture, calibration probes, source hashes, and deliberate-stall timestamps. Compare fixed-latency calibration against the measurement segment to detect clock drift or recording discontinuities; do not fit a time-varying correction to force a pass.

An independent forward-mixture model now reproduces retained two-second original F06/F08 windows with RMS differences2.17e-12/1.33e-9. Fifteen counterexample tests and independent source review cover missing attacks, late admission, erased voices, duplicated64-voice batches, search limits and periodic aliases. This is measurement preparation: the old freely searched lag does not qualify absolute timing, and finite profile sampling cannot exclude every alternative. Complete new original-fixture capture, independent calibration and ambiguity analysis remain required. See [method and limits](../evidence/step-05/original-mixture/Method.md) and [independent review](../evidence/step-05/original-mixture/Independent-Review.md).

## Completed measured observations

The analytic route run recorded 132 isolated onsets, using its first 12 to estimate a fixed 13.4375 ms latency and the remaining 120 to evaluate timing. It detected every planned onset, with no extra detections; compensated error was below one sample. Its actual 100/250 ms stalls and raw recording are retained in the root report. These observations establish the route, not the full composition gate.

The actual product run completed on 2026-10-11, using the immutable `evidence/step-10/soak-source` bundle. It calibrated from 12 F02 onset groups, then measured **144 independently identified groups**: 20 remaining F02 original chord groups, 36 F03 groups with note duration shortened to 0.05 seconds, 40 F06 sentinel groups, and 48 F08 sentinel groups. Expected arrivals are calculated from saved vertex vectors, scene parameters, emission periods, nearest-grid quantization, and independent 64-voice ownership simulation. The first emission supplies a common transport anchor; scheduled trigger/onset timestamps are not used as measured audio arrivals.

Compensated median absolute error was **0.020833 ms**, p95 **0.062500 ms**, and maximum **0.062500 ms**, with zero missing groups and zero unmatched detections inside measurement windows. Both dense variants recorded actual 100/250 ms main-thread stalls, with each of the four stalls spanning an independently predicted and PCM-measured audible onset. The F06/F08 variants retained all 92 pieces, four/eight generators, all target events, long-lived silent voices, and the 64-voice cap. They made only the final beat audible with a 0.03-second decay. That alteration permits independent onset detection, but does not establish timing or listening quality of the original dense mix. The prior complete attempt, whose 100 ms stalls fell between audible groups, is preserved in `product-attempt-02-stall-window-miss/`.

Original F06 and F08 were also recorded for eight seconds each. Both reached 64 voices and an actual recorded peak of approximately 0.98; pending counts observed were at most 336 and 652 respectively. Their individual audible onsets remain unidentified. The original recordings and complete variant scenes are retained in the product report, so these limitations are reviewable.

The final product recording contains 6,963,200 samples at 48 kHz. Chunk-clock continuity showed no discontinuities over half a sample; the maximum numerical deviation was below 0.000000002 samples. Incremental recording includes 15 additional tail chunks received during analysis; the final recording and measured errors use the earlier explicit prefix. The paused baseline peak was zero. A single **13.416667 ms** constant derived from product onsets was removed, with no slope or time-varying correction. Because the reference was the product itself, calibration can absorb a constant product delay. These residuals establish conditional timing stability, not absolute product-onset latency; the report explicitly sets `absoluteOnsetTimingQualified: false`. The analytic synth probe also calibrates from its own output and qualifies the route only. The report records exact bundle/fixture hashes and the harness hash used at capture time. `product/capture-harness.ts` preserves the exact capture-time script and matches that hash; later evidence-derivation additions to the current script are separate. That bundle predates later lifecycle fixes; these observations do not qualify a newer unmeasured revision.

Actual audiovisual synchronization requires its own ≥30 captured events and frame timestamps. A physical room listening/direction test and venue-renderer interpolation qualification remain external gates.

## Thirty-minute dense soak

`scripts/soak.ts` records a real 1,800-second Chrome F06 session, with 30-second validated tempo/degree/atomic-note-swap edits and 60-second audio/render/CDP memory samples. It snapshots the built bundle before launch to prevent development hot reload from invalidating continuous playback. The evidence-only immutable server uses `http://127.0.0.1:5420/BongoPlanet/`; the permanent application remains `http://127.0.0.1:5417/BongoPlanet/`.

The unmuted headless run completed **1,800.125 real seconds**, starting **2026-10-11 17:19:48.347 UTC (20:19:48.347 Istanbul)**; cleanup finished at 17:49:48.554 UTC. It retained 59 validated edits and 30 status samples, with running audio, 92 pieces, at most 64 voices and 336 pending events, and zero observed late/telemetry drops. There were no uncaught exceptions. Warm-up heap use ranged from 40.2–74.1 MB (median 55.0 MB); the last five minutes ranged from 39.4–95.9 MB (median 53.2 MB). Render geometries remained within the same observed 1,250–1,590 range. No sustained rise in heap floors or object counts was observed; see `soak-review.md` and `soak-review.json` for the measured scope and limits.

The first headed attempt ended after 210.12 seconds when its browser closed; its reports/source snapshot are retained as `soak-attempt-01-*`. A subsequent muted headless attempt is retained as `soak-attempt-02-*` and was intentionally stopped to correct its route. Neither counts toward the completed unmuted timer. The successful browser/context closed with exit code 0, and the evidence-only 5420 listener disappeared. No further probes ran after that closure.

The successful soak uses an earlier immutable bundle. Both main and processor compiled hashes differ from final commit `62bccbabffd5523feae2b92358907faa00f706ae`; exact comparisons are in the final review. Later warm-up, UI, output, and lifecycle fixes were regression-tested separately by the lead. This evidence does not qualify that newer revision for a full 30-minute run. Audio was routed to the named cable during the soak but was not recorded continuously; missing audible events across all 30 minutes are not independently counted.

The two startup console 404 messages were independently reproduced with the same immutable F06 load/enable/sink/play sequence. CDP response URLs and console locations identify both as `http://127.0.0.1:5420/favicon.ico`, Chrome's fallback icon request outside the project path. See `soak-http-diagnostic-full-startup.json`. This attribution does not remove the two messages from the soak report or turn its console-error check into a pass. No uncaught playback error had been observed at the time of that attribution.

`system-audio-after-probes.json` verifies that after recording the system default output remains MacBook Pro Speakers at 48 kHz and the default input remains the physical microphone. Only explicitly selected virtual inputs were opened for capture; all probe tracks and contexts were destroyed afterward.

The product worklet is excluded from those calibration probes, so its constant delay cannot be absorbed. The measured fixed route latency is 13.333333 ms.
