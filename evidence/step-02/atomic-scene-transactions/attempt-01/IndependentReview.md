# Bongo Planet — independent atomic scene operation review

The retained nine passing tests and unchanged source support **S02-A20 and S02-A21 at the model-operation boundary**. This matches Step 02's requirement to implement additions/deletions as atomic model operations. It does not establish transactional rollback across rendering, audio, output, history, or browser interaction. No test or browser was rerun for this review.

`changeScene` clones the complete input before calling the mutation callback and returns only after validating the complete draft. A callback or validation exception therefore prevents a candidate result from being returned while leaving the original scene intact. The UI uses that exact boundary: placement passes the result of `changeScene(...push(newPiece(...)))` to `apply`, and deletion passes the result of `changeScene(...filter(...))`. JavaScript evaluates those arguments before invoking `apply`, so a rejected model change cannot reach its history push or scene assignment. `apply` also validates before those writes.

The actual report contains nine named passing assertions and zero failures. Successful additions cover generator, note, and beat; successful deletions cover each corresponding piece. The tests compare the complete original scene serialization after the operation and again after mutating the returned candidate's nested data. Rejected additions cover occupied vertex, duplicate ID, out-of-range vertex, and a ninth generator, including valid changes made earlier in the draft callback. Rejected deletion covers both a callback exception and final schema rejection after the deletion and another draft edit. These are meaningful failure/aliasing checks, not merely assertions that the helper returns.

The success cases inspect settings plus piece identity/vertex/kind (add) or retained IDs (delete); they do not deep-compare every unchanged sound field in the returned candidate. A future transform that changed an unrelated output field could evade those success assertions. Current source has no such transform, and the operation isolation/rollback assertions independently cover the stated atomicity property. Optional strengthening would compare the entire successful candidate with a declared expected scene. Removing the last piece, deleting an absent ID, and an addition callback throwing are not explicit cases; none is a blocker to the scoped conclusion because the same clone/callback/validate boundary handles them. These tests make no concurrency, asynchronous callback, or external-side-effect guarantee.

In particular, `apply` updates the model and then calls view/audio/output adapters sequentially. This evidence does not claim that a later adapter exception rolls back earlier adapter/model/history effects. That is outside the focused Step 02 model claim and must not be included in the ledger wording.
