## Two constructed failure scenarios repaired during review

### A valid calibration could be reused as both before and after

The initial auditor independently detected native click PCM, but did not establish where its calibration belonged in the segment sequence. Given one valid calibration object, copying it into both `calibrationBefore` and `calibrationAfter` would give equal lag and could pass; the same object could also be reused across segments. That would provide no evidence that the route remained stable after playback.

The revised source binds each calibration's actual support to its own integer `retainedBlocksBefore`/`retainedBlocksAfter` range. It requires before support to precede analysis, after support to follow both the timer and the 200 ms analysis tail, and the two retention intervals to be ordered. Each following segment's calibration chain must follow the preceding after support/retention. The checks use original observer indices, so repeated context-clock values cannot excuse reused support. Readback confirms that the constructed reuse/overlap cases fail these checks. No mutation test was executed during capture preparation.

### Missing event provenance could pass an otherwise intact PCM audit

The initial auditor never opened `events.jsonl`. Deleting or truncating that file could therefore still leave `captureIntegrityAuditPassed=true`, and `firstEmission` would be trusted only from the summary report. Subsequent analysis would have lost the separately retained record that anchors its fixed epoch.

The revised source streams the full event file, verifies original global and per-segment indices, contiguous batch identity/order, finite receive clocks, and exact event/batch counts against capture statistics. It hashes the event file and binds each segment's reported first emission—including the full event and both receive clocks—to that segment's first retained actual emission. Missing files, truncation, ordering failures, or an uncorroborated epoch now fail. Production emits only nonempty telemetry batches, consistent with the auditor's contiguous visible-batch check.
