# Bongo Planet capacity test correction

The original failed artifact is preserved as `original-failed-phase-burst.json` (SHA256 `41fd2b32e44299dc12bd995b70f67f8056a7182f9f6abe8ab41d0bbfbede7fbe`). The corrected test is frozen at SHA256 `c7858543417879cf7bcc1af85d42914cf2ca90665f0b98a508c56582be2ba954`. Production code was not changed.

The original test assumed 40 BPM forever even after requesting 180 BPM. With initial emission at 0.256000000 s, the declared change takes effect at beat 1, 1.756000000 s. The correct transport map is B(t)=(t-anchor)×40/60 before that boundary, and B(t)=1+(t-boundary)×180/60 afterwards. Phase edits join the future eight-beat grid. At edit 7, phase×8 was 1.024888889, whose first-cycle time under the correct clock is 1.764296296 s. Subsequent chosen phases are provably already past the captured audio clock: at edit 8 the correct first-cycle time is about 1.917185185 s but audioNow is 2.421333333 s. They consequently join later cycles instead of producing the intended immediate burst. The original sampled pending peak was 5,336, below 5,376, and no capacity reset occurred.

The old barrier also used the number of emissions in a bounded event ring. That count fell 80→79→77→73 as rows expired, so a changed count could falsely signal an emission. The revised barrier requires actual emission identity and target time. It does not infer emission from a ring count or status sequence.

The corrected test derives the future target from the greater of the current audio clock and last independently observed processor-status time, plus the original 60 ms lead; it converts through the declared piecewise clock and wraps the phase within the legal eight-beat cycle. Before a capacity interruption, all eight declared generators must emit at that target. The guard-interrupting row is identified by the actual reset event because status telemetry may arrive later. The application module hash now selects the main script rather than the dev server's first `@vite/client` script. The destination is configurable, and each new attempt retains its exact test source.

Attempt 01 reached the real capacity reset, then failed the newly added completeness assertion because the last reset-interrupted emission had only one generator while the previous telemetry still said running. That artifact is retained. Attempt 02 passed all original assertions in an actual Chrome run: one test, 11.7 s (13.3 s total), exit 0. It reached the cap after eight phase edits in 985.800 ms. Pre-overflow pending was exactly 5,376; reset sequence was 5,377 at transport beat 0.680000000.

The visible pending-limit explanation persisted through five seconds, Enable, and an unrelated timbre edit. Transport stayed paused with zero pending and zero voices; no additional onsets or output reconnection occurred. Explicit Play recovered. After the preserved tempo boundary, beat delta 6.232000000000 over 2.077333333333 s measured exactly 180 BPM. There were no browser errors and the served main-module hash stayed unchanged. Playwright closed the browser; no services were changed.

Capacity-specific remote voice release remains unmeasured because the bridge output stays disconnected for this isolated test. In this passing attempt the capacity reset preceded the first audible onset, so the zero-voice result does not independently prove a fade of already active voices. No synthetic reset, fake processor error, artificial pending insertion or weakened capacity/recovery threshold was used. Full-suite revalidation remains root-owned.
