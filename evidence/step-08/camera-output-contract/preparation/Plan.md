# Bongo Planet — camera/output contract source plan

This is source preparation only. Root must separately authorize one actual; no browser, receiver, port probe or check is launched during the UI quiet hold. Permanent5417/5418 services and production sources stay unchanged.

The proposed test uses the frozen5417 production application and an exclusively owned ordinary unchanged native bridge with HTTP/WS/UDP port0. An exact WebSocket URL substitution routes only the application's `ws://127.0.0.1:5418` producer to that temporary bridge. No application adapter, renderer, topology, clock or interpolation code is replaced. The browser remains paused/locked with no generators and no PCM/microphone/output-device operation. A bounded send witness observes original position packets and public `view.getDiagnostics().camera`; it never changes sent packets. Private receiver raw OSC bytes, object/position states and native readiness/failure state are retained.

**Static camera case:** load paused F07, require all six hand-specified nearest-axis coordinates (independent normalized `(3phi,0,1)` permutations/signs and fixed vertex IDs). A trusted empty-canvas orbit must move the public camera by a measurable amount; a trusted wheel zoom must change its radius. Both actions must preserve the exact whole scene and exact receiver object/node IDs and world XYZ. Merely sending a gesture without observing a camera change cannot pass. This narrowly supports S08-A9 camera-presentation independence for this Chrome configuration; it does not inspect hidden Three matrix internals or prove all camera configurations/venues.

**Moving camera case:** at60/15/2 render FPS, use a one-note paused scene, predeclare right85→forward10 as a legal empty-destination relocation, and commit through production `__bongo.edit`. Capture the browser performance bracket surrounding that edit, then make a trusted empty-canvas orbit during its120ms source transition. Require actual production position packets and corresponding receiver positions/decoded raw UDP before and after a witnessed camera change, with intermediate positions on both sides. Stable object identity, exact final model, monotonic shortest-arc progress and final independent coordinates within1e-6 must hold. The analytic expected path uses the hand-known endpoints only, never camera-relative coordinates or production `surfacePoint`/topology. A camera change after the interpolation ends cannot pass the concurrent case.

The120ms comparison uses the position packet's producer `sent` timestamp, the retained chosen startup offset and the browser edit-time bracket. The common offset cancels; a declared1ms browser timestamp precision premise is retained. It is a conditional same-browser monotonic control trace, not a proven continuous cross-host clock bound, receiver scheduling gate, physical audio clock or presentation latency measurement. Native receiver readiness/uncertainty>10ms or any failure/drop fails the run; no retry, deadline retargeting or fallback occurs. The existing40/60ms receiver age gates are separate and are not asserted from sparse clocks here.

Packets/observations are explicitly bounded; capture overflow fails rather than silently losing evidence. Every observed movement packet must have an ordered matching receiver position and independent decoded UDP packet; no empty/missing prefix can pass. Static and movement cases remain separately reported. No sustained active sound is created, so active-voice following, venue interpolation and audible/visual onset human gates remain open.

Any timeout/forced/unconfirmed cleanup is failed and scoped explicitly, not promoted to success.
