## What the public option changes

`WebSocketServer` defaults `allowSynchronousEvents` to true and passes it to the receiver. For uncompressed text messages, `receiver.js` emits synchronously when true. When false, it sets `DEFER_EVENT`, schedules `setImmediate`, emits the message there and then resumes parsing. Binary messages and ping/pong have corresponding deferred paths. This gives other callbacks an opportunity to run between messages; it is not an ACK credit protocol, a guaranteed worker scheduling quantum, or a fixed-latency promise.

The text path explicitly permits synchronous emission while its state is `INFLATING`, even with the option false. Therefore both experiment arms must bind and assert the same no-compression negotiation (the installed server default is `perMessageDeflate:false`) and actual text-frame type. The option also affects ping/pong scheduling. Those implications must remain visible in a later production decision rather than being described as universal one-message-per-tick behavior under every transport configuration.

The actual prior error string identifies the parent NativeClock admission guard, whose alternatives are maximum single-command bytes, unacknowledged count and unacknowledged bytes. The failed capture does not contain the instantaneous failing counter. Plan01's introductory reference to the 262,144-byte/8,192-command limits should be read as the guard's limits, not as a measurement proving which alternative fired. Its 29.393666 ms reference is after the Node resume **acknowledgement**; request-relative elapsed is 29.795666 ms.

## Meaningful equal-workload comparison

1. Freeze **identical intended payloads**, object/sequence order, serialization and send-attempt strategy before either execution. Do not require identical *accepted* payloads: earlier baseline rejection is a possible result. Account planned, attempted, completed-send, server-received, admitted, applied, rejected and OSC-received denominators separately. Do not silently shorten the second arm to the baseline's admitted prefix, or continue treating a missing suffix as a pass.
2. Use fresh isolated processes and the same quiescent readiness boundary for both arms: valid clock, expected session, no pending/active voices, initial object state as declared, and no unacknowledged bootstrap work before the burst. If a 92-object seed is separate from the approximately 1,200-position burst, identify and ACK-drain it identically, with separate counts. Otherwise seed commands must be part of the same predeclared denominator.
3. If absolute `sent` times/session identifiers must differ between runs, freeze a relative-time/identity instantiation recipe and retain both realized payloads. Never recenter timestamps after observing a failure. Bind the same client settings, compression state, native source, Node/ws versions and loopback delivery strategy. Public `send` boundaries do not determine TCP chunk boundaries; record the actual server callback groupings needed to interpret the result instead of assuming equal kernel segmentation.
4. A successor completes only after **all** intended position admissions, ordered native applied acknowledgements, receiver outputs and independently decoded OSC outputs are reconciled, with expected final state, zero forbidden failure/drop and empty outstanding work. Lower peak counters or an alive socket alone are not success: deferred input could merely still be waiting. Keep a fixed deadline and any unchanged freshness/watchdog rules; a late/missing suffix, stale positions or backlog at completion remains a failure.
5. A baseline that does not reproduce the admission failure is a valid nonreproduction, not permission to enlarge the burst until it does. A successor failure is also retained. One paired observation is conditional evidence for this fixture and host, without statistical repeatability or a claim that every earlier failure shares the same cause.

## Instrumentation and cascade checks

Instrument the same immutable copies in both arms. At minimum the trace should distinguish server message callback entry/exit, parent post attempt/admission with command sequence and bytes plus count/byte values before/after, and worker-message callback entry/exit with each applied acknowledgement's decrement. A shared parent-domain monotonically increasing trace ordinal makes ordering inspectable without assuming cross-thread timestamps alone establish callback interleaving. Retain the failing attempted row before fail-closed transition when capacity permits; if observation capacity prevents it, declare the diagnostic incomplete.

Do not yield, poll, execute private work, issue extra control messages or change timers from the tracing path. In-memory bounded primitive records are preferable to synchronous disk/JSON work per message. Even identical instrumentation can perturb the arms differently because different numbers of messages survive; report this limitation and preserve source diffs. The trace can establish that admissions accumulated while no applied-ACK callback ran. It must not turn that into an unmeasured OS or worker-starvation diagnosis.

The installed flag preserves parsing order but changes delivery relative to timers, close handling and worker ACKs. A slower successor may allow a watchdog to expire or positions to age even while solving command-capacity pressure. Do not prevent that outcome by injecting extra heartbeats, extending leases, resetting the session or changing the fixture between arms. If heartbeat traffic is necessary, predeclare its identical schedule and inclusion in the denominator before execution. There are no musical triggers in the planned fixture, so the 20 ms onset rule, cancel-versus-onset races, and position-before-trigger behavior are **unchanged source contracts, not empirically verified by this experiment**. They require separately scoped existing or future tests before a production change is accepted.

The roughly 1,200-position scale fits below the existing 5,000-entry receiver/OSC rings only if seeding and cleanup are also counted; prove that bound or fail on any wrap. No uncapped observation reservoir or private queue may hide work when the receiver rejects it.

Bind the exact command and allowed claims; reject malformed/unknown live ownership rather than signaling numeric recycled identities. Preserve already established cleanup defenses: inspect/release parent handles independently, latch late stdio faults, await native process closure, and distinguish forced/unknown closure from success. Confirm loopback-only ephemeral TCP/UDP ownership and avoid permanent services.

They are cooperative or sampled bounds subject to host descheduling, not unconditional preemption guarantees.
