# Bongo Planet — root acquisition controller source

Source-only candidate; this file grants no actual-run authorization. One later root GO will bind the final reviewed helper, controller, configuration, served production assets and review artifacts before acquisition. The existing failed source candidate remains preserved.

The external Python controller permits only the fixed Playwright command and an exact root authorization phrase. It creates an exclusive PID-claim JSONL outside the attempt directory before launch. The helper must synchronously append each proxy and Chromium server PID immediately upon acquisition, including late browser fulfillment, before awaiting readiness. Each claim is bounded to the fixed schema and validated against current OS ancestry plus retained process start signatures. The controller also retains recursively observed descendants. Successful two-arm acquisition requires two claims of each resource kind.

Main allowance is 80 seconds, total allowance 100 seconds; these are cooperative wall checks, not OS hard deadlines. Process-table sampling uses bounded one-second ps commands. The controller cannot prove ownership of an unobserved resource reparented before its claim can be validated; this causes an incomplete/failing run. ps lstart has second precision, so this is a practical PID reuse guard, not a high-resolution kernel birth attestation. No private or global unrelated processes are targeted.

Any controller error, timeout, surviving owned process, malformed/partial/oversized claim, or forced cleanup fails the run. Cleanup first attempts pending claims, then uses independent process inventory so malformed claims or journal-write errors cannot prevent termination of already verified descendants. It gives TERM three seconds then KILL two seconds and retains final inventory and exit status; unknown final inventory fails. The final journal write can fail, in which case stdout retains the error and the run fails after cleanup. Filesystem writes and scheduler delays are not hard bounded.

Eight pure controls cover parsing, recursive detached descendants, reused/absent parent rejection, zombie/reused PID exclusion, malformed/capped inventory, and full simulated cleanup after invalid claims or disk-write failure. These simulations launch no processes and send no signals. A separate prior read-only ps parser check parsed 1012 rows. No live cleanup or acquisition has occurred under this controller.
