## Feasibility judgment

A byte-transparent owned TCP proxy with a small native receive buffer is a plausible bounded experiment, but cannot guarantee the complete witness. SO_RCVBUF restricts the proxy's input queue; it does not set Chromium's send queue, Mojo buffers or TCP acknowledgment behavior. Kernel clamping/window scaling and sender buffering can absorb all allowed movement before the500ms receiver lease expires. The only acceptable proof of crossing is the original browser socket's actual read-only bufferedAmount>65,536, not proxy bytes queued or an estimate. The [WebSockets Standard](https://websockets.spec.whatwg.org/#dom-websocket-bufferedamount) defines this application-visible queued amount; [Apple's socket manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/setsockopt.2.html) documents input/output buffer options and system limits. These are mechanism references, not measurements of this host's socket defaults.

Two independent deadlines start at different events: the receiver lease expires500ms after its last heartbeat, while OutputAdapter starts its movement timer only on a tick that observes high bufferedAmount. Stopping receiver-side reads can therefore expire the receiver before the sender's own timer. A proposed drain arm is valid only if actual threshold crossing and recovery both fit inside the receiver lease. Failure to cross promptly is an acquisition limitation, not a product fail or permission to extend the lease. An early receiver close cannot be presented as the sender's500ms congestion action.

Current source has a20ms movement service, a100ms heartbeat, no heartbeat while the tick begins above the cap, and a strict `> .5` sender timeout. Its movement loop checks the actual buffer between packets; no artificial send is needed. At91 moving/sound objects and50Hz there is enough possible movement volume to make the experiment plausible, but rate alone cannot prove browser pressure. Parent bridge20ms and native worker25ms watchdogs race: native release may be self-watchdog or a forwarded parent-watchdog stop. Report the actual reason/actor. A result cannot silently certify independent native self-watchdog if only a forwarded stop is observed.

## Proposed isolated topology

Use a Python standard-library nonblocking raw TCP proxy bound only127.0.0.1:5426, forwarding exclusively to an untouched temporary `createBridge(5427,5428,{nativeClock:true})`. Reserve5428 for its owned loopback UDP receiver. A later implementation must preflight all three ports and reject conflicts; do not touch permanent5417/5418 or select alternate ports. Native clock/bridge/protocol modules are imported unchanged, frozen by source SHA before GO; bind actual main/worklet response hashes and hand-scene JSON too. Present HTTP status queries may go directly to the private bridge outside the congested producer path.

Only the producer's exact `ws://127.0.0.1:5418` constructor URL maps to5426. Preserve browser native WebSocket, Origin, path, handshake, masking, compression negotiation and every byte in both directions. Do not terminate/recreate WebSockets, decode and selectively forward frames, reorder/drop bytes or synthesize heartbeats. The proxy may passively retain bounded binary prefixes/counts; original browser sends and original receiver records supply packet semantics. Request SO_RCVBUF=1,024 on the listening/accepted sockets and retain actual getsockopt values/errors; no clamp guarantee. Leave Chromium socket options untouched. Proxy user-space queues must be bounded and native partial writes handled without data loss; if a bound is exceeded, preserve the failure and stop.

Pause **raw reads in both directions** for sustained congestion. This preserves receiver-generated close bytes behind the same indiscriminate pause, permitting the sender's own close call to be observed separately. The receiver still runs its independent native heartbeat watchdog; its release/state is queried directly. This is an explicit transport impairment and must not be described as ordinary uncongested loopback. In the short-drain arm resume both directions before the receiver lease expires. Keep every retained byte FIFO; a peer's prior closure remains a recorded closure, never a resumed healthy connection.

Browser instrumentation calls the original send/close exactly once, without changing arguments, timing policy or outcomes, and records actual before/after bufferedAmount/readyState, monotonic timestamps, native close code/reason and sent JSON identity. A20ms read-only sampler observes the actual routed socket; a MutationObserver records actual #output-state transitions. No private tick, recovery set or cached-last field is read/changed. Retain instrumentation as a perturbation; bufferedAmount itself is not overridden. A source review must ensure observers cannot introduce diagnostic traffic or reorder sends.

## Two fresh finite arms

Each arm owns a fresh browser/context, proxy connection and native bridge incarnation; identical scene/default render settings. Fixed order drain then sustain is disclosed. Startup has a20second cap per arm, including eight producer clock probes, native ready/healthy checks and the optional genuine active-voice prelude. No timer is anchored to mere launch. Preserve session/incarnation and state immediately before impairment.

**Drain arm.** Immediately after an actually forwarded heartbeat, pause reads, keep legal edits running, and monitor real bufferedAmount. If no crossing is observed within250ms of pause, resume/retain **threshold-not-reached** and do not certify the arm. If crossing occurs, hold about40ms and resume no later than350ms after pause, independently requiring the last native heartbeat's age still below400ms. The resume acknowledgement itself must meet that bound; a late controller command invalidates the intervention. Actual limits are conservative acquisition deadlines, not changes to500ms product tolerances. Stop edits at the predetermined final permutation; retain150ms settling plus bounded delivery observation. Require actual buffer drainage, the same live session, no close/drop/clock error, both unchanged sentinels and every current object freshly represented after recovery, stable IDs/monotonic position sequences, eventual final XYZ at the latest settled scene, and no first-object-only replay. All preceding stale queued positions remain in order; do not discard them from the trace. The full latest snapshot needs positive evidence, not merely final state after later edits happened to dirty every object.

**Sustained arm.** Repeat the same active/prelude and true pressure activation once. Do not resume either direction until the browser's own native close call/actual visible status is retained, or1.2seconds after first high observation. Require a meaningful continuous above-cap interval and no intervening low-buffer sample; if observation gaps make the start ambiguous, retain the bounded interval and mark exact-duration proof incomplete. First-high send/sample and20ms sampler bracket sender detection; require no sender congestion close earlier than500ms from first-high evidence, and a visible `Disconnected · control backpressure` transition (plus close1000/reasoncontrol backpressure). A receiver-close first is a distinct outcome. Do not turn close handshake delay into the congestion interval.

Direct bridge/native state sampling must independently retain lastHeartbeatHrNs, a positive active-voice state, release mutation brackets/reason, zero pending/active/objects afterward and no revival from later buffered heartbeats. Compute heartbeat→release in the native hrtime domain; do not subtract browser and Node clocks without a independently bounded mapping. Preserve whether native self-watchdog or parent watchdog originated release. The numerical subset fails/incomplete if the voice naturally expired, no release row survives retention, clock invalidation instead caused release, or actor/timing cannot be identified. Native watchdog check cadence and mutation overhead are reported, not silently called exactly500.000ms. Resume raw reads afterward only to retain closure/error tails, not to retry or restore the old session.

## Bounds, retention and stop conditions

Suggested fixed budget for later source review:100seconds total cooperative hard-controller deadline, reserving20seconds cleanup; acquisition stops by80seconds. Each pressure episode≤1.2seconds, edits≤50Hz and≤150edits/arm, no more than16,384 native send observations/arm or32,768 total;16MiB total serialized diagnostic trace,8MiB total raw proxy bytes and64KiB user-space output queue per direction. Exact byte accounting/capacity arithmetic must be source-reviewed before execution. Cap native/state snapshots and retain critical release rows by direct sampling during the quiet blocked interval; a rolling64-row witness cannot silently stand for a complete high-rate trace. If any needed row is overwritten or trace cap hit, declare evidence loss/incomplete. No silent truncation.

Retain scene/full raw send and read/write prefix metadata, requested/effective socket options, proxy pause/resume times, real buffer samples, actual forwarding/read/write byte totals, all UI transitions/close reasons, original receiver position/control/UDP records, native incarnation/state/release and before/after served asset/source hashes. Browser→proxy→native clocks stay separate unless independently mapped; same-domain durations are primary. A supplementary send-to-receive byte/packet join must not use cross-clock subtraction as transit latency proof.

Stop immediately on actual product/context/clock/socket/proxy errors or ownership/cap failures; retain first cause and incomplete remainder, no retry. Resume proxy reads for bounded cleanup, pause/dispose/close AudioContext, close browser/context and require owned browser process exit; close sockets/listener, untouched temporary bridge/worker/UDP and proxy process, confirm observed owned process groups absent and5426/5427TCP plus5428UDP released. Separate controller watchdog must kill only positively owned resources if graceful cleanup fails and preserve forced cleanup as failure. No default audio/device routing changes or microphone access. Source-only parser/partial-write/ownership/deadline controls and independent review precede any actual GO.

**Decision:** feasible enough for one separately reviewed bounded source prototype; not sufficient to promise the full S01-A43 witness. If true pressure cannot occur inside the short-drain heartbeat budget, or source preparation cannot retain the native release without modifying production, decline qualification and keep the missing witness open.
