## S01-A43: historical control overflow is narrower

[backpressure.json](../step-09/backpressure.json), dated 2026-10-11 18:26:40 UTC, retains seven position receipts after 1,000 synchronous edits, then 199 attempted trigger-loop iterations, maximum actual socket buffer 65,826 bytes, and status `Disconnected · control backpressure`. The [source-adapter browser test](../../tests/output-browser.spec.ts:106) creates a separately imported Vite OutputAdapter and floods trigger controls. `send()` immediately closes above 65,536 bytes. In contrast, `tick()` returns while movement is congested, retains unsent position state, and closes only after elapsed congestion exceeds 0.5 seconds. The trigger flood does not exercise that duration branch. Its status array is a callback witness, not a screenshot/assertion of the integrated `#output-state` UI. The historical JSON also has no served adapter hash. The earlier independent review's adapter hash `1de9d6f1…` differs from current `bd46913c…`; use current V2 evidence for applicable ordinary streams instead of claiming the older congestion record is a final-bundle rerun.

The receiver's missing-heartbeat watchdog tests concern another mechanism. They cannot establish the producer's movement-congestion timer or latest-snapshot resumption. A future closing witness would need actual movement-only congestion, retained buffer/time/send traces, a drained latest-state receipt, and a separate sustained-congestion visible disconnect plus receiver release. No such run was authorized or performed in this audit.
